# Политика конфиденциальности - Belyaev Response

**Версия документа:** 1.0 · **Дата:** 15 августа 2026 · **Относится к версии продукта:** 1.5.3+

## 1. Кто мы

Belyaev Response - браузерное расширение для SOC-аналитиков, разработанное на основе
концепции Дмитрия Беляева (vCISO, независимый эксперт, belyaev.expert). Настоящая
политика описывает, какие данные обрабатывает расширение и сопутствующий сервер
лицензирования.

## 2. Общий принцип

Расширение спроектировано по принципу **локальности данных**: по умолчанию вся
обработка происходит в браузере аналитика, ничего не отправляется на серверы
разработчика, потому что  у разработчика имеется только сервер лицензирования.


## 3. Какие данные обрабатываются и где

### 3.1. Данные, которые НИКОГДА не покидают браузер
- Извлечённые из карточки инцидента индикаторы компрометации (IOC), текст заголовка/
  описания - обрабатываются локально для отображения в панели, MITRE-маппинга,
  генерации черновиков отчётов и заключений.
- API-ключи (VirusTotal, AbuseIPDB, Anthropic), токены ботов (Telegram, MAX), webhook-
  URL - хранятся в `chrome.storage.local` в зашифрованном виде (AES-256-GCM),
  расшифровываются только в фоновом контексте расширения (`background.js`) в момент
  фактического сетевого запроса.
- История событий/инцидентов, прогресс наставника, баланс BelZor - локальное
  хранилище браузера, не синхронизируется с серверами разработчика.

### 3.2. Данные, отправляемые во внешние TI-сервисы (по явному действию аналитика)
При нажатии кнопки «проверить» рядом с конкретным индикатором значение этого
индикатора (IP/домен/хэш) отправляется в VirusTotal и/или AbuseIPDB с использованием
API-ключа, указанного самим аналитиком в настройках. Это происходит только по клику,
не автоматически.

### 3.3. Данные, отправляемые в LLM (Anthropic API или локальная модель)
Перед отправкой текста в LLM (кнопки с пометкой «✨»/Pro) расширение **автоматически
заменяет** на плейсхолдеры: IP/MAC-адреса, email, SSH/AWS-ключи, JWT-токены, учётные
записи (по ключевым словам и формату `DOMAIN\user`) и заданные пользователем названия
компании. Перед отправкой аналитик видит точное превью того, что будет отправлено
(«🔒 Обезличено перед отправкой»). Модель никогда не получает исходные значения -
только плейсхолдеры вида `[[IP_1]]`; подстановка обратно в реальные значения
происходит локально, при отображении ответа.

Для организаций, которым нельзя отправлять данные во внешние облачные LLM даже в
обезличенном виде, предусмотрена работа с локальной LLM (Ollama-совместимый API) -
в этом случае данные не покидают инфраструктуру организации вообще.

### 3.4. Данные, отправляемые на сервер лицензирования (только при активной Pro-лицензии)
Сервер лицензирования - не сервис разработчика, а инфраструктура, которую организация
разворачивает и администрирует самостоятельно (см. `/license-server` в поставке).
Расширение обменивается с ним следующими данными:

| Функция | Что передаётся |
|---|---|
| Активация лицензии | лицензионный ключ, случайный идентификатор устройства (генерируется локально) |
| Синхронизация с Grafana (опционально, выключено по умолчанию) | псевдоним аналитика (задаётся пользователем, не обязан быть реальным именем), агрегированные счётчики (баланс BelZor, число событий/инцидентов, разбивка по вердиктам) - **без содержимого карточек, без IOC, без текста инцидентов** |
| Маркетплейс адаптеров | конфигурация адаптера (URL-паттерны, CSS-селекторы) - технические данные, не содержащие информации об инцидентах |
| Глоссарий терминов | текст термина/определения, который аналитик сам решил опубликовать, привязан к организации (не к личности) через лицензионный ключ |

Синхронизация с Grafana **выключена по умолчанию** и требует явного включения в
настройках. Псевдоним для рейтинга аналитик может оставить пустым/произвольным -
расширение не требует указывать реальное имя.

### 3.5. Данные, отправляемые в уведомления команде (Slack/Telegram/MAX/Teams/Jira)
Только по явному нажатию кнопки рассылки заключения - отправляется краткая сводка
(заголовок инцидента, вердикт, причина, ссылка) на канал/сервис, который сама
организация настроила в своих учётных данных. Это внутренняя коммуникация с
коллегами, не с разработчиком.

## 4. Что расширение НЕ делает

- Не собирает и не передаёт разработчику историю браузера, посетённые сайты или
  личные данные пользователя вне карточек инцидентов SIEM.
- Не активируется автоматически на произвольных сайтах - только на страницах,
  соответствующих настроенным адаптерам (универсальный fallback-адаптер, способный
  сработать на любом сайте, по умолчанию **выключен** и требует осознанного включения
  с явным предупреждением о последствиях - см. CHANGELOG v1.5.0).
- Не продаёт и не передаёт третьим лицам какие-либо данные.
- Не показывает рекламу.
- Не выполняет автоматических деструктивных действий (блокировка IP, изоляция хоста
  и т.п.) - все шаблоны команд реагирования предоставляются только как текст для
  ручного копирования и запуска аналитиком.

## 5. Хранение и удаление данных

- Все локальные данные хранятся в `chrome.storage.local` браузера аналитика и
  удаляются при удалении расширения либо вручную через очистку данных расширения в
  настройках браузера.
- Данные на сервере лицензирования (если используется) хранятся в зашифрованном виде
  (AES-256-GCM) и управляются политикой хранения самой организации
  обратитесь к вашему администратору SOC/ИБ за деталями хранения данных в вашей
  организации.

## 6. Права аналитика

- Обезличивание перед LLM работает всегда для соответствующих функций и не может быть
  отключено пользователем - это осознанное защитное ограничение, а не настройка.
- Использование внешних TI-сервисов, LLM и рассылок в мессенджеры требует явного
  указания собственных API-ключей/токенов - без них соответствующие функции просто не
  работают, автоматической отправки без ключа быть не может.
- Псевдоним для командного рейтинга - по желанию, не обязателен к заполнению реальным
  именем.

## 7. Изменения политики

Эта политика обновляется вместе с изменениями функциональности продукта, требующими
уточнения обработки данных. Актуальная версия поставляется вместе с расширением в
файле `PRIVACY_POLICY.md`.
